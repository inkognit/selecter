## Этап 4. Бэкенд — 22.10.2026

- Стек: NestJS 11.2 (CommonJS), TypeScript 5.9, Prisma 7.10 + `@prisma/adapter-pg`, Jest 30.
  Отступление от «последних версий»: Nest 12 вышел ESM-only, а ts-jest не поддерживает
  TypeScript 7 — на проверенной связке меньше риска для тестового задания.
- `core/` — конфиг (проверка env на старте, единственное место с `process.env`), один
  `PrismaService`. `common/` — конверт `{ success, data, meta, error }`, глобальный фильтр
  ошибок, 422 с перечнем полей.
- Модуль `tasks` в четыре слоя: `domain` (правила позиций — чистые функции), `application`
  (сервис, порт `TASKS_REPOSITORY`, коды ошибок), `infrastructure` (Prisma-репозиторий:
  транзакция + `pg_advisory_xact_lock`, переиндексация одним `UPDATE … unnest` в обход
  `@updatedAt`, SQLSTATE → доменные ошибки), `presentation` (тонкий контроллер, DTO
  запроса и ответа раздельно, `TaskIdPipe`: не-UUID → 404).
- Swagger: `http://localhost:3500/api/docs`.
- Тесты:
  - unit (44): правила позиций, сервис на in-memory фейке порта, конфиг, сторож слоёв
    `architecture.spec.ts` (правила A-1…A-6, проверен на заведомых нарушениях — и сразу
    поймал настоящее: `process.env` в `core.module.ts`, исправлено);
  - e2e (21) против живого PostgreSQL в отдельной базе `kanban_test`: CRUD, переносы,
    позиции без дыр, `updatedAt` соседей не меняется, параллельные операции, негатив
    (422/404), маппинг SQLSTATE `23505`/`23514` в доменные ошибки.
- Проверка измерителя: без advisory-lock тест параллельных операций падает 3 из 3 —
  блокировка действительно нужна и тест её ловит.
- Smoke: `npm run build` → `node dist/main.js` на рабочей базе: health, список (6 демо-задач,
  e2e их не тронули), создание → перенос → удаление, Swagger 200, CORS для `:3501`.
  Без `DATABASE_URL` старт падает с `ConfigError`.
- `tsc --noEmit` и `eslint` чисто. Удалены `test-server/` и `test-client/` (Р-4).
