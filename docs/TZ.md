# ТЗ: канбан-доска задач

Версия 1 от 22.10.2026. Общий план работы и принятые решения — в [PROMPT.md](PROMPT.md).

## 1. Цель

Веб-приложение для ведения задач по методологии канбан: одна доска, три колонки, задача
движется между колонками. Данные хранятся в PostgreSQL и переживают перезагрузку страницы и
перезапуск сервера. Приложение одинаково удобно на компьютере и на телефоне.

## 2. Границы

**Входит:** одна общая доска, CRUD задач, перенос между колонками и порядок внутри колонки,
адаптивная вёрстка, состояния загрузки, ошибки и пустой доски.

**Не входит** (записывается в ограничения README): авторизация и пользователи, несколько
досок, исполнители, сроки, метки, комментарии, вложения, история изменений, поиск и
фильтры, синхронизация между вкладками в реальном времени, пагинация.

## 3. Сущность «Задача»

| Поле          | Тип                     | Правила                                                                  |
| ------------- | ----------------------- | ------------------------------------------------------------------------ |
| `id`          | UUID                    | генерирует БД                                                            |
| `title`       | строка                  | обязательно; пробелы по краям обрезаются; после обрезки 1–200 символов   |
| `description` | строка или `null`       | необязательно; до 5000 символов; пустая строка после обрезки → `null`    |
| `priority`    | `LOW`/`MEDIUM`/`HIGH`   | по умолчанию `MEDIUM`                                                    |
| `status`      | `NEW`/`IN_PROGRESS`/`DONE` | при создании всегда `NEW`; меняется только переносом                   |
| `position`    | целое ≥ 0               | порядок внутри колонки, 0 — сверху; позиции в колонке идут подряд без дыр |
| `createdAt`   | дата-время              | ставит БД                                                                |
| `updatedAt`   | дата-время              | обновляется при любом изменении                                          |

Подписи на интерфейсе:

- статусы: `NEW` — «Новая», `IN_PROGRESS` — «В работе», `DONE` — «Готово»;
- приоритеты: `LOW` — «Низкий», `MEDIUM` — «Средний», `HIGH` — «Высокий».

## 4. Функциональные требования

### Ф-1. Доска

- Три колонки в порядке «Новая», «В работе», «Готово». У каждой — название и число задач.
- Задачи в колонке отсортированы по `position`.
- Карточка показывает название, чип приоритета (цвет по уровню) и первые 2–3 строки
  описания с многоточием.

### Ф-2. Создание задачи

- Кнопка «Новая задача» (на телефоне — плавающая кнопка) открывает форму: название,
  описание, приоритет.
- Ошибки валидации показываются у поля до отправки; сервер повторяет те же проверки.
- Новая задача попадает в конец колонки «Новая».
- На время запроса кнопка «Создать» заблокирована — двойной клик не создаёт две задачи.

### Ф-3. Просмотр

- Клик по карточке открывает диалог с полными данными: название, описание с переносами
  строк, приоритет, статус, даты создания и изменения.

### Ф-4. Редактирование

- Из диалога просмотра — кнопка «Редактировать»: меняются название, описание, приоритет.
- «Отмена» возвращает исходные значения без запроса к серверу.

### Ф-5. Удаление

- Кнопка «Удалить» в диалоге; удаление только после подтверждения.
- Позиции оставшихся задач колонки сдвигаются, дыр не остаётся.

### Ф-6. Перемещение

- Десктоп: перетаскивание карточки в другую колонку или на другое место в своей колонке.
- Телефон и клавиатура: меню «Переместить в…» на карточке и в диалоге — задача уходит в
  конец выбранной колонки.
- Перемещение отображается сразу; если сервер вернул ошибку, карточка возвращается на
  прежнее место и показывается сообщение.
- Позиция, выходящая за пределы колонки, приводится к ближайшей допустимой (в конец или в
  начало), а не считается ошибкой.

### Ф-7. Сохранение данных

- Все изменения сразу записываются в БД. После перезагрузки страницы доска выглядит так же.

### Ф-8. Состояния интерфейса

| Состояние       | Что видит пользователь                                                         |
| --------------- | ------------------------------------------------------------------------------ |
| Загрузка доски  | скелетоны карточек в колонках                                                  |
| Ошибка загрузки | текст причины и кнопка «Повторить»; «сервер недоступен» отличается от «ошибка сервера» |
| Пустая доска    | иллюстрация/текст «Задач пока нет» и кнопка «Создать первую задачу»            |
| Пустая колонка  | подпись «Нет задач» внутри колонки                                             |
| Ошибка действия | всплывающее сообщение (Snackbar) с понятным текстом                            |
| Успех действия  | короткое всплывающее сообщение («Задача создана», «Задача удалена»)            |

## 5. API

Префикс `/api/v1`. Каждый ответ — конверт:

```json
{ "success": true, "data": {}, "meta": null, "error": null }
{ "success": false, "data": null, "meta": null, "error": { "code": "task_not_found", "details": null } }
```

| Метод  | Путь              | Тело запроса                            | Ответ `data`       |
| ------ | ----------------- | --------------------------------------- | ------------------ |
| GET    | `/tasks`          | —                                       | `Task[]`           |
| GET    | `/tasks/:id`      | —                                       | `Task`             |
| POST   | `/tasks`          | `{ title, description?, priority? }`    | `Task`             |
| PATCH  | `/tasks/:id`      | `{ title?, description?, priority? }`   | `Task`             |
| PATCH  | `/tasks/:id/move` | `{ status, position }`                  | `Task`             |
| DELETE | `/tasks/:id`      | —                                       | `{ id }`           |
| GET    | `/health`         | —                                       | `{ status: "ok" }` |

Коды ошибок:

| Код                 | HTTP | Когда                                                     |
| ------------------- | ---- | --------------------------------------------------------- |
| `task_not_found`    | 404  | задачи нет или `id` не UUID                               |
| `validation_failed` | 422  | неверное тело запроса, лишнее поле, неизвестный enum      |
| `task_conflict`     | 409  | нарушена уникальность позиции в колонке (см. DB.md, раздел 3) |
| `internal_error`    | 500  | всё остальное; подробности только в логах сервера         |

Человеческие тексты ошибок формирует фронт по коду, сервер их не отдаёт.

## 6. Нефункциональные требования

- **Адаптивность:** ширина от 360px; на экране < 768px колонки показываются вкладками.
- **Доступность:** все действия выполнимы с клавиатуры; у кнопок-иконок есть `aria-label`.
- **Надёжность данных:** правила длины названия и непрерывность позиций обеспечиваются и в
  коде, и в БД (ограничения + транзакции).
- **Запуск:** одной конфигурацией из VS Code Run and Debug; база поднимается в Docker,
  миграции и демо-данные накатываются автоматически.
- **Качество:** `tsc` и lint без ошибок, тесты ключевой логики зелёные, smoke в браузере
  с 0 ошибок консоли.

## 7. Ключевая логика под тестами

1. Создание: обрезка пробелов, валидация длины, задача уходит в конец колонки `NEW`.
2. Перенос между колонками: позиции в исходной и целевой колонках остаются непрерывными.
3. Перестановка внутри колонки: вверх и вниз, с приведением позиции к допустимой.
4. Удаление: позиции оставшихся сдвигаются.
5. Негатив: несуществующая задача → `task_not_found`; пустое название, лишнее поле,
   неизвестный статус → `validation_failed`.

## 8. Известные ограничения версии 1

- Одновременное редактирование в двух вкладках: побеждает последняя запись.
- Нет пагинации: доска рассчитана на сотни задач, не на десятки тысяч.
- Нет авторизации: доска общая для всех, кто открыл приложение.
