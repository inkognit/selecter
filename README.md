# Канбан-доска задач

Тестовое задание: упрощённая Jira по методологии канбан. Одна доска, три колонки
(«Новая», «В работе», «Готово»), задачи можно создавать, смотреть, править, удалять и
переносить между колонками. Данные хранятся в PostgreSQL. Вёрстка работает на компьютере
и на телефоне.

**Стек:** NestJS 11, Prisma 7, PostgreSQL 16, Next.js 16 (App Router), React 19, MUI 9,
TanStack Query, dnd-kit.

## Запуск

### Что нужно

- Node.js 22 (проверено на 22.14);
- Docker Desktop — должен быть запущен;
- VS Code.

### Из VS Code (основной способ)

1. Открыть папку репозитория в VS Code.
2. Run and Debug (`Ctrl+Shift+D`) → выбрать **«ВСЁ · API + веб»** → `F5`.
3. Браузер откроется сам на <http://localhost:3501>.

Перед стартом API задача `api: подготовка` из [.vscode/tasks.json](.vscode/tasks.json)
сама выполнит шаги по порядку:

1. создаст `.env` из `.env.example`, если его ещё нет;
2. поставит зависимости бэкенда;
3. поднимет PostgreSQL в Docker (`docker compose up -d --wait` ждёт healthcheck);
4. накатит миграции (`prisma migrate deploy`);
5. запишет демо-задачи из [backend/prisma/initial.sql](backend/prisma/initial.sql);
6. соберёт бэкенд.

Веб стартует параллельно: ставит свои зависимости и ждёт ответа `/api/v1/health`.
Первый запуск занимает 1–3 минуты, в основном это `npm install`.

Другие конфигурации:

| Конфигурация                               | Когда                                              |
| ------------------------------------------ | -------------------------------------------------- |
| ВСЁ · на уже поднятых контейнерах          | база уже поднята — только сборка и старт           |
| Тесты · бэкенд unit                        | база не нужна                                      |
| Тесты · бэкенд e2e                         | поднимет базу; тесты идут в отдельной базе `kanban_test` |
| Тесты · веб                                | vitest                                             |

Стереть базу целиком: `Terminal → Run Task → infra: reset (стирает данные)`. При следующем
запуске доска вернётся к демо-задачам.

**Демо-задачи записываются один раз за жизнь базы** (отметка в таблице `seed_history`).
Удалённые демо-задачи при перезапуске не вернутся — поэтому можно проверить пустую доску.

## Структура

```text
backend/                 NestJS API
  prisma/                schema.prisma, migrations/, initial.sql (демо-данные)
  src/core/              конфиг (проверка env на старте), один PrismaService
  src/common/            конверт ответа API, глобальный фильтр ошибок
  src/modules/tasks/
    domain/              правила позиций — чистые функции
    application/         сервис, порт хранилища, коды ошибок
    infrastructure/      репозиторий на Prisma (транзакция + блокировка доски)
    presentation/        контроллер, DTO запроса и ответа
  src/architecture.spec.ts   тест, который держит направление зависимостей слоёв
  test/                  e2e
web/                     Next.js
  src/api/               единственный API-клиент и тексты ошибок
  src/features/board/    модель доски, хуки данных, компоненты
docs/                    PROMPT.md (план работы), TZ.md, DESIGN.md, DB.md
```

## Решения

- **Архитектура бэкенда** — по правилам проектов WeGo и gonets:
  - модуль в четыре слоя (domain / application / infrastructure / presentation);
  - сервис зависит от интерфейса хранилища, а не от Prisma;
  - контроллер тонкий, DTO запроса и ответа — разные классы;
  - направление зависимостей проверяет тест, а не ревью.
- **Единый формат ответа** `{ success, data, meta, error }`. Ошибки — машинные коды
  (`task_not_found`, `validation_failed`, `task_conflict`, `internal_error`), текст для
  человека формирует фронт в одном месте.
- **Порядок задач** — целые позиции 0, 1, 2… без дыр. Инварианты продублированы в БД:
  - `CHECK` на длины;
  - `UNIQUE (status, position) DEFERRABLE` — отложенная проверка разрешает переиндексацию
    колонки одним `UPDATE`.

  Нарушение ограничения превращается в 409/422, а не в 500.
- **Параллельные запросы.** Все изменения порядка идут в транзакции под
  `pg_advisory_xact_lock`. Доска одна, поэтому очередь дешевле разбора гонок. Тест на
  параллельные переносы без блокировки падает 3 раза из 3, с блокировкой проходит.
- **Перенос на фронте оптимистичный:** карточка встаёт на место сразу, при ошибке
  возвращается обратно.
- **Телефон (< 768px):** колонки — вкладки, перетаскивание выключено (на тач-экране оно
  спорит с прокруткой), перенос — через меню «Переместить в…».
- **Прокси `/api` через Next:** нет CORS, доска открывается с телефона без доступа к
  порту API.
- **Версии.** NestJS 11 и TypeScript 5.9 вместо самых свежих: NestJS 12 вышел только в ESM,
  а ts-jest не поддерживает TypeScript 7.

Подробнее: [docs/TZ.md](docs/TZ.md), [docs/DESIGN.md](docs/DESIGN.md), [docs/DB.md](docs/DB.md).

## Ограничения

- Нет авторизации и пользователей: доска общая для всех, кто её открыл.
- Одна доска; нет исполнителей, сроков, меток, комментариев, истории, поиска и фильтров.
- Одновременная правка одной задачи в двух вкладках: побеждает последняя запись.
  Другая вкладка увидит изменения при возврате фокуса или следующем действии.
- Нет пагинации: доска рассчитана на сотни задач, не на десятки тысяч.
- Создание задачи не идемпотентно на сервере. Двойной клик закрыт на фронте блокировкой
  кнопки, но два одинаковых запроса от разных клиентов создадут две задачи.
- На телефоне нельзя поменять порядок внутри колонки: «Переместить в…» ставит задачу в
  конец колонки.
- Новые миграции Prisma нужно проверять вручную: Prisma не знает, что `UNIQUE` отложенный
  (порядок — в [docs/DB.md](docs/DB.md), раздел 5).
